我把 Obsidian 当 AI 的外置大脑用，让 agent 通过官方 CLI 读写笔记。某次让它去读几篇旧笔记，它回来说：那几篇是空的。

那几篇不是空的。我自己在 Obsidian 里看得见内容。

## 症状

非交互地执行读取命令：

```bash
obsidian read "大脑主页"
echo "exit=$?"
```

输出：

```
exit=0
```

一个字都没有，退出码 0。

这是整件事最坑的地方。**如果它报错，我三十秒就能定位**。返回空加成功状态，等于 CLI 在说「我读了，那篇确实什么都没有」。于是我的第一反应是去查笔记路径对不对、文件名有没有空格、vault 是不是没索引——全都在错误的方向上。

## 怎么定位到的

转折点是我意识到「exit 0 + stdout 空」这个组合本身就是个签名。

程序会区分「输出给人看」和「输出给管道」的场景非常常见——`ls` 会在管道里去掉颜色和分栏，`git log` 不接 TTY 就不分页。这类判断都靠 `isatty(1)`。如果某个工具把**整个输出**都放在了「给人看」的分支里，那么一旦没有 TTY，它就什么都不打印，而且它认为自己成功了，所以退出码是 0。

验证只要一行——手动塞一个伪终端进去，其他条件全不变：

```bash
script -qec 'obsidian read "大脑主页"' /dev/null
```

内容全出来了。

同一条命令，同一个 vault，同一个笔记名。唯一的变量是 stdout 那头是不是终端。到这里就结案了。

## 修法

把调用包一层。`script` 分配一个伪终端，`-q` 去掉它自己的开场白，`-e` 把真实退出码透传出来（没有 `-e` 的话你拿到的是 `script` 自己的退出码，等于又给自己埋一个坑），`/dev/null` 是丢掉它的 typescript 文件。

```bash
obs() {
  script -qec "obsidian $*" /dev/null
}

obs read "大脑主页"
obs search "锁屏"
```

上面这个是 Linux（util-linux 版 `script`）的写法，我在 openSUSE 上用的就是它。BSD 系包括 macOS 的 `script` 参数顺序不同，但我没有 mac 可以验，所以不在这里写具体命令——要跨平台的话，用 `python3` 起个 `pty` 比赌 `script` 的方言更稳。

## 真正的教训

这件事值得写下来，不是因为 obsidian CLI 有多重要，而是因为**它属于「静默失败」这一类**，而这类 bug 在 agent 工具链里代价特别大。

人遇到空输出会怀疑工具。agent 遇到空输出会**如实汇报**「这篇笔记是空的」，然后基于这个错误前提继续往下做决策。它没说谎，它拿到的就是空的。整条链路上没有任何一处报错，于是错误一路传到最后。

所以现在我给 agent 包装的每个外部命令都加一条断言：**成功的调用不许返回空**。空就是异常，往上抛，不许当成有效结果。这一条比修好这个具体的 CLI 有用得多。
